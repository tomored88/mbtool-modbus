## ไม่มีคำตอบจากอุปกรณ์ (timeout)
<!-- id: trouble-no-response | category: แก้ปัญหา | keywords: ไม่ตอบ timeout no response เงียบ ต่อไม่ติด แก้ปัญหา ตรวจสอบ -->
ตรวจตามลำดับ (ง่ายและพบบ่อยก่อน)

1. **อุปกรณ์มีไฟ** และอยู่ในโหมด Modbus (บางรุ่นต้องเปิดโปรโตคอล Modbus ในเมนู เช่น ADAM, DTSU666)
2. **Slave ID ถูก** ดูที่หน้าจออุปกรณ์ ถ้าไม่ทราบใช้ [[scanner]]
3. **baud / parity / stop bits ตรงกัน** ([[serial-settings]]) ผิดค่าเดียวก็ไม่ตอบ
4. **สาย A/B ไม่สลับ** ลองสลับสองเส้น ([[rs485-wiring]])
5. **พอร์ตไม่ถูกโปรแกรมอื่นถือ** ([[trouble-port-busy]])
6. **โหมดตรงกัน** RTU หรือ ASCII ([[rtu-vs-ascii]])
7. TCP: ping ได้ไหม firewall ปิดพอร์ต 502 ไหม IP/พอร์ตถูกไหม
8. ดู [[traffic-monitor]] ว่ามี RX บ้างไหม ถ้ามี RX แต่เป็น error แปลว่ามีสัญญาณ ([[trouble-crc]])
9. **timeout บางครั้ง ไม่ใช่ทุกครั้ง:** อุปกรณ์อาจตอบช้ากว่า timeout ที่ตั้งไว้ เพิ่ม Timeout ใน Setup ให้มากกว่าเวลาตอบที่ช้าที่สุด บน RTU ถ้าคำตอบมาช้ากว่า timeout โปรแกรมจะรอฟังสายอีกสั้น ๆ (0.15 วินาที) แล้วทิ้งคำตอบที่มาช้า แต่ถ้ามาช้ากว่านั้นมาก คำตอบเก่าอาจถูกนับเป็นคำตอบของคำขอถัดไป เพราะเฟรม RTU ไม่มีหมายเลขกำกับ (TCP ไม่มีปัญหานี้ เพราะมี Transaction ID)
10. **TCP หลุด:** ถ้าอุปกรณ์ปิดการเชื่อมต่อหรือส่งข้อมูลเสีย โปรแกรมจะทิ้งการเชื่อมต่อนั้นและต่อใหม่เองในคำขอถัดไป

## CRC / LRC error บ่อย
<!-- id: trouble-crc | category: แก้ปัญหา | keywords: crc error บ่อย ข้อมูลเสีย noise รบกวน termination สายยาว ผิดบางครั้ง -->
- **ผิดตลอด:** baud หรือ parity ไม่ตรง ลอง [[scanner]]
- **ผิดบางครั้ง:** สัญญาณรบกวน ขาด termination 120 Ω ที่ปลายสาย สายยาวเกินหรือไม่ใช่สายตีเกลียว ไม่มี bias ใช้สายร่วมกับสายไฟแรงสูง
- **ผิดเมื่อมีหลายอุปกรณ์:** มี master สองตัวพูดพร้อมกัน หรือ Slave ID ซ้ำกัน
- ตัวแปลง USB-serial ราคาถูกบางรุ่นทำให้เฟรมขาดช่วง ลองลด baud หรือเปลี่ยนตัวแปลง
- ใน Devices ลองเพิ่มช่วงเว้นระหว่างอุปกรณ์

## พอร์ต COM ถูกใช้อยู่ (busy)
<!-- id: trouble-port-busy | category: แก้ปัญหา | keywords: port busy com ถูกใช้ access denied permission พอร์ต ปิด โปรแกรมอื่น -->
พอร์ตเปิดได้ทีละโปรแกรมเดียว (ภายในโปรแกรมนี้ Poll 1, แท็บ และอุปกรณ์แชร์พอร์ตเดียวกันได้ ดู [[poll-tabs]]) ปิดโปรแกรมอื่นที่ใช้พอร์ตนั้น (โปรแกรมตั้งค่าของผู้ผลิต, โปรแกรม Modbus master ตัวอื่น, อีก instance ของโปรแกรมนี้) ถ้า MCP server (stdio) เปิดพอร์ตอยู่ GUI จะเปิดไม่ได้ และกลับกัน ใช้ AI Assist ที่แชร์การเชื่อมต่อของ GUI แทน ([[ai-assist]]) ถ้าถอด USB แล้วเสียบใหม่ ให้กด Refresh

## ค่าที่อ่านได้ไม่ตรงกับหน้าจอเครื่อง
<!-- id: trouble-values-wrong | category: แก้ปัญหา | keywords: ค่าไม่ตรง ผิด เพี้ยน แปลก float สลับ เหลื่อม scale ค่าประหลาด -->
ไล่ตามลำดับ

1. **เหลื่อมไป 1 register?** ลองฐาน address อื่น (Address base หรือ "Try other base") ([[address-bases]])
2. **ชนิดข้อมูลผิด?** ค่า Float ที่ดูเป็นเลขแปลก ๆ (เช่น 1e-38 หรือ 1e+30) เกือบแน่ใจว่าลำดับ word ผิด ใช้ตัวตรวจค่า F4 ([[inspector]], [[word-order]])
3. **ลืม scale?** ค่า 253 ที่ควรเป็น 25.3 → scale 0.1 ([[scale-offset]])
4. **Signed หรือ Unsigned?** อุณหภูมิติดลบแสดงเป็น 65xxx แปลว่าต้อง Signed
5. **FC ผิด?** ลอง FC03 เทียบ FC04 ([[fc03]], [[fc04]])
6. **ค่าจากอุปกรณ์เก่า/ถูกแคช** บางรุ่นอัปเดตค่าช้า เทียบหลายรอบ (ใช้ snapshot หรือกราฟ)
7. **preset ยังไม่ยืนยัน** ([[verified-presets]]) เทียบกับคู่มือฉบับล่าสุดของรุ่นนั้น

## Exception 02 ตอนอ่านหลายค่า
<!-- id: trouble-exc2-block | category: แก้ปัญหา | keywords: exception 02 อ่านหลายค่า คร่อม ขอบตาราง block ช่องว่าง -->
อ่านทีละตัวผ่านก็ได้ แต่อ่านหลายตัวพร้อมกันได้ exception 02 แปลว่าช่วงที่ขอคร่อมขอบตาราง หรือมีช่องที่อุปกรณ์ไม่ให้อ่านคั่นอยู่ ใช้ `scanner.py regs` หา ranges ที่อ่านได้ แล้วตั้ง preset ให้แยกคำขอ (ลด `max_block` หรือกำหนดกลุ่ม) ดู [[exc02]]

## หลาย master บนสายเดียว
<!-- id: trouble-multimaster | category: แก้ปัญหา | keywords: หลาย master พร้อมกัน ชน collision สองโปรแกรม -->
Modbus RTU/ASCII มี master ได้ตัวเดียวต่อสาย ถ้ามี PLC กำลัง poll อยู่แล้วเอาโปรแกรมนี้ไปต่อสายเดียวกัน คำขอจะชนกันและเกิด CRC error/timeout สลับกัน ให้หยุด master ตัวใดตัวหนึ่ง หรือต่อผ่าน gateway ที่รวมคำขอ หรือใช้ Modbus/TCP แทน (แต่ละการเชื่อมต่อแยกกัน)

## เขียนค่าแล้วไม่เปลี่ยน
<!-- id: trouble-write-fail | category: แก้ปัญหา | keywords: เขียนไม่ได้ write ไม่เปลี่ยน read only ไม่มีผล ปฏิเสธ exception เขียน -->
- ได้ exception 01/02/03? ตรวจว่า register นั้นเขียนได้และค่าอยู่ในช่วง ([[exceptions]])
- ไม่มี error แต่ค่าไม่เปลี่ยน: อุปกรณ์อาจต้องปลดล็อก/ใส่รหัสผ่านก่อน (เช่น SDM630 System type) หรืออยู่ในโหมดที่ห้ามแก้ หรือค่าถูกเขียนทับจากระบบควบคุมทันที
- ค่า 32 บิตต้องเขียนด้วย [[fc16]] ในคำขอเดียว และลำดับ word ต้องตรง ([[word-order]])
- บางค่าต้องเขียนแล้วสั่ง "บันทึก/ใช้" แยกอีกตัวตามคู่มือ
