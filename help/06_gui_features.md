## แผง Poll: Slave ID, Function, Address, Quantity, Scan Rate, Display
<!-- id: poll-panel | category: ฟีเจอร์ในโปรแกรม | keywords: poll panel slave id function address quantity scan rate display แผง ตั้งค่า อ่านค่า -->
กำหนดว่าจะอ่านอะไรจากอุปกรณ์

- **Slave ID:** หมายเลขอุปกรณ์ 1–247 บน serial ส่วน TCP รับ 0–255 (เช่น gateway บางรุ่นใช้ 0 หรือ 255) ([[slave-id]])
- **Function:** FC01–FC04 สำหรับอ่าน ([[data-areas]])
- **Address:** address เริ่มต้น ตามฐานที่เลือกใน Address base ([[address-bases]]) ใต้ช่องแสดง `= protocol N` ที่จะส่งจริง
- **Quantity:** จำนวนที่อ่าน ดู [[limits]] ถ้าขึ้น exception 03 ให้ลดลง
- **Scan Rate:** ช่วงเวลาระหว่างการอ่านแต่ละรอบ (มิลลิวินาที) ขั้นต่ำ 20 ms สายอนุกรมช้า ๆ ตั้งสูงกว่าเวลาที่คำขอใช้จริง
- **Display:** รูปแบบแสดงผล ([[display-formats]]) ติ๊ก **Multi-type view** ใต้ช่องนี้เพื่อดูหลายชนิดข้อมูลพร้อมกัน ([[multi-view]])
- **Rows per column:** จำนวนแถวต่อคอลัมน์ 10/20/30/40 หรือ Auto ตารางเรียงลงทีละคอลัมน์ตามจำนวนที่เลือก

ช่องที่กรอกผิดจะมีข้อความแดงใต้ช่อง และการ poll หยุดจนกว่าจะแก้

ต้องการอ่านหลายชุดพร้อมกัน (คนละ Slave ID / คนละช่วง address / คนละอุปกรณ์) เปิดแท็บ poll เพิ่มด้วยปุ่ม **+** หรือ Ctrl+T: ดู [[poll-tabs]]

## แท็บ Poll: หลาย poll พร้อมกันในหน้าต่างหลัก
<!-- id: poll-tabs | category: ฟีเจอร์ในโปรแกรม | keywords: poll tabs tab แท็บ หลายแท็บ หลาย poll หลายหน้าต่าง new tab แท็บใหม่ ปิดแท็บ เปลี่ยนชื่อ rename duplicate ทำซ้ำ ctrl+t ctrl+w same as connection custom -->
หน้าต่างหลักมีแถบแท็บอยู่ใต้ toolbar แต่ละแท็บคือ poll หนึ่งชุด เหมือนเปิดหน้าต่าง poll หลายหน้าต่าง: มี Slave ID, Function, Address, Quantity, Scan Rate, Display, Address base และ Rows per column ของตัวเอง และ **ทุกแท็บอ่านพร้อมกัน** ([[poll-panel]])

- **แท็บแรก (Poll 1)** คือ poll หลักแบบเดิมทุกอย่าง ปุ่ม Connect (F5), Setup (F3), preset view (F7), log (Ctrl+L) และ AI Assist ทำงานกับแท็บนี้ แท็บแรกปิดไม่ได้ (เปลี่ยนชื่อได้)
- **แท็บใหม่:** ปุ่ม **+** ท้ายแถบแท็บ, Ctrl+T หรือ File → New poll tab ได้แท็บ "Poll 2", "Poll 3"... ที่ตั้งค่าเริ่มต้นเหมือนแท็บที่เปิดอยู่ (Slave ID, function, address, quantity, scan rate, display) แก้ได้ทันที ถ้าแท็บต้นทางกำลังอ่าน แท็บใหม่เริ่มอ่านเอง
- แต่ละแท็บมีปุ่ม **Start/Stop** ของตัวเอง และบรรทัดสถานะด้านล่างแท็บ: จุดสี ข้อความล่าสุด เวลาอัปเดตล่าสุด ตัวนับ OK / error และ error ล่าสุด แก้ poll definition ระหว่างที่อ่านอยู่ แท็บจะเริ่มอ่านใหม่ด้วยค่าใหม่เมื่อหยุดพิมพ์
- **จุดสีหน้าชื่อแท็บ:** เขียว = อ่านได้, แดง = error, ส้ม = ไม่มีคำตอบนานแล้ว (หรือแท็บแรกกำลังเชื่อมต่อ), เทา = หยุดอยู่
- **ตาราง:** เหมือนแท็บแรก ([[grid]]) ค่าที่เปลี่ยนกะพริบเหลือง อ่านไม่ได้เป็นสีเทา ดับเบิลคลิก (หรือ Enter) เพื่อเขียน ใช้กับ FC01 (coil) และ FC03 (holding register) ติ๊ก Multi-type view ได้ ([[multi-view]]) ปุ่ม Columns... ใช้ชุดคอลัมน์เดียวกันทุกแท็บ
- **F6** เปิดหน้าต่างเขียนค่า ([[write-dialog]]) ที่เขียนผ่านการเชื่อมต่อของแท็บที่เปิดอยู่ (ชื่อแท็บอยู่บนหัวหน้าต่าง) **F4** ตรวจค่าช่องที่เลือกในแท็บนั้น ([[inspector]])
- **Preset...:** แสดงค่าตามชื่อจาก preset แทนตาราง (Point, Value, Unit, Raw, Status แบบเดียวกับ [[devices-tabs]]) ในแท็บนี้อ่านอย่างเดียว ปุ่ม **Register grid** กลับไปตารางปกติ
- **คลิกขวาที่ชื่อแท็บ:** Rename... (หรือดับเบิลคลิกชื่อ พิมพ์แล้ว Enter, Esc ยกเลิก), Duplicate tab (ทำซ้ำรวม preset และการเชื่อมต่อ), Start/Stop polling, Show in Devices window, Close tab (หรือคลิกปุ่มกลางเมาส์ / Ctrl+W)
- **ปิดแท็บ** = หยุดอ่านและลบแท็บนั้นเท่านั้น ไม่ถามยืนยัน ไม่กระทบแท็บหรืออุปกรณ์อื่น กฎแจ้งเตือนของแท็บยังอยู่ ลบได้ใน Alerts
- **สลับแท็บ:** คลิก, Ctrl+Tab / Ctrl+Shift+Tab, Ctrl+PgUp / Ctrl+PgDn ถ้าแท็บเยอะจนเกินความกว้างหน้าต่าง ใช้ปุ่ม ◀ ▶ หรือหมุนล้อเมาส์บนแถบแท็บ ปุ่ม ▾ แสดงรายการทุกแท็บพร้อมสถานะ

**การเชื่อมต่อของแท็บ**
- **Same as Poll 1 connection** (ค่าเริ่มต้น): ใช้ค่าเดียวกับแท็บแรก และตามไปเมื่อเปลี่ยนใน Setup (F3) แท็บที่กำลังอ่านจะเริ่มใหม่ด้วยค่าใหม่ แต่ละแท็บเปิดการเชื่อมต่อ (TCP socket) ของตัวเอง จึงไม่ต้องกด Connect ในแท็บแรก
- **Custom connection** หรือปุ่ม **Setup...**: ตั้ง TCP / RTU / ASCII ของแท็บนี้เอง เช่น อ่านอุปกรณ์สองตัวคนละ IP เลือก Same as... อีกครั้งเพื่อกลับไปใช้ค่าของแท็บแรก
- **COM port เดียวกันใช้ร่วมกันได้** ทั้ง Poll 1, แท็บอื่น และอุปกรณ์ใน Devices: โปรแกรมเปิดพอร์ตเพียงครั้งเดียวแล้วให้ทุกคน **ผลัดกันส่งทีละคำขอ** (คำขอหนึ่งส่งและรับคำตอบจบก่อนคำขอถัดไป) เหมือน PLC ที่ไล่อ่านทีละ telegram ตัวไหนที่มาถึงก่อนก็ได้ใช้สายก่อน ทุกตัวต้องตั้ง **baud / parity / stop bits เหมือนกัน** เพราะเป็นสายเส้นเดียว (ถ้าไม่เหมือนจะขึ้นข้อความบอก) พอร์ตปิดเมื่อทุกตัวเลิกใช้ ถ้าอยากเห็นเวลาของแต่ละรอบ ใช้โหมด PLC cycle ใน [[devices]] ([[plc-cycle]])

**ความสัมพันธ์กับ Devices (F11)**
แท็บที่สองขึ้นไปเก็บเป็นอุปกรณ์หนึ่งตัวในรายการ Devices (ชื่อเดียวกับแท็บ) จึงเห็นในตาราง Overview และมีแท็บในหน้าต่าง Devices ด้วย ใช้ Trend, Alerts, log แยกไฟล์ต่ออุปกรณ์ ([[logging]]) และ PLC cycle ([[plc-cycle]]) ได้เหมือนอุปกรณ์อื่น Start all / Stop all ในหน้าต่าง Devices รวมแท็บเหล่านี้ด้วย Remove ใน Devices = ปิดแท็บ แก้ด้วย Edit... แล้วแท็บแสดงค่าใหม่ทันที

**การบันทึก:** แท็บ (poll definition, การเชื่อมต่อ, Display, address base, rows, multi-type) เก็บในการตั้งค่าและใน workspace ([[workspace]]) เปิดโปรแกรมใหม่แท็บกลับมาครบแต่หยุดอยู่ (workspace ที่บันทึกตอนอุปกรณ์กำลังอ่านจะเริ่มอ่านเอง) ชื่อแท็บแรกและแท็บที่เลือกไว้ถูกจำด้วย Demo devices ไม่สร้างแท็บและไม่ถูกบันทึก

**ข้อจำกัด**
- คนละโปรแกรมใช้ COM เดียวกันไม่ได้ (เช่น โปรแกรมตั้งค่าของผู้ผลิต หรือโปรแกรม Modbus master ตัวอื่นเปิดพอร์ตอยู่) ดู [[trouble-port-busy]] การแชร์ทำได้เฉพาะภายในโปรแกรมนี้ และการอ่านหลายตัวบนสายเดียวช้ากว่าอ่านทีละสายเพราะต้องผลัดกัน
- อุปกรณ์ TCP บางรุ่นรับการเชื่อมต่อพร้อมกันได้น้อย (เช่น 1–4) แต่ละแท็บใช้ 1 การเชื่อมต่อ ถ้าแท็บใหม่ต่อไม่ได้ให้ลดจำนวนแท็บ
- ปุ่ม Connect / F5, log Ctrl+L, preset view F7 และ AI Assist เป็นของแท็บแรกเท่านั้น
- แท็บที่แสดง preset เขียนค่าตามชื่อจุดไม่ได้ ใช้ F6 เขียนตาม address หรือ preset view ในแท็บแรก

## ตารางค่าและการแก้ไขค่า
<!-- id: grid | category: ฟีเจอร์ในโปรแกรม | keywords: ตาราง grid แก้ไข edit double click เขียนค่า กะพริบ highlight ค่าเปลี่ยน -->
- ค่าที่เปลี่ยนจากรอบก่อนกะพริบสีเหลือง ค่าจากรอบที่ล้มเหลวเป็นสีเทา
- **ดับเบิลคลิก** (หรือเลือกแล้วกด Enter/F2) เพื่อแก้ค่าในช่อง ใช้กับ FC01 (coil) และ FC03 (holding register) ค่าถูกเขียนตามรูปแบบ Display (เช่น Float เขียน 2 register)
- ค่าผิดรูปแบบหรือนอกช่วงแสดงข้อความแดงในช่อง กด Esc เพื่อยกเลิก
- คลิกขวา → "Inspect value..." เปิดตัวตรวจค่า ([[inspector]])
- FC02/FC04 อ่านอย่างเดียว

## Multi-type view: ดูหลายชนิดข้อมูลพร้อมกัน
<!-- id: multi-view | category: ฟีเจอร์ในโปรแกรม | keywords: multi-type view multi type หลายชนิด หลาย type พร้อมกัน display เดียว columns คอลัมน์ unsigned signed hex binary float long ascii ตาราง -->
ติ๊ก **Multi-type view** ใต้ช่อง Display ในแผง Poll (หรือเมนู Tools → Multi-type view) ตารางปกติจะเปลี่ยนเป็นตารางที่มี **1 แถวต่อ 1 register** และ **1 คอลัมน์ต่อ 1 ชนิดข้อมูล** เช่น Unsigned, Signed, Hex, Binary, Float, Long จึงเห็นว่า register เดียวกันอ่านเป็นแบบไหนได้ค่าที่สมเหตุสมผล โดยไม่ต้องสลับ Display ไปมา

- ปุ่ม **Columns...** (แทนที่ Rows per column ขณะเปิดโหมดนี้) เลือกคอลัมน์ได้จากทุกรูปแบบใน [[display-formats]] รวม Inverse และ ASCII (2 ตัวอักษรต่อ register) ค่าที่เลือกและสถานะเปิด/ปิดถูกจำไว้ในการตั้งค่าและใน workspace ([[workspace]])
- Address แสดงตามฐานที่เลือกใน Address base ([[address-bases]])
- ชนิดที่ใช้หลาย register (Long/Float ใช้ 2 ตัว, Double ใช้ 4 ตัว, ลำดับ word ของ Inverse ดู [[word-order]]) **แสดงค่าเฉพาะแถวที่เริ่มค่า** นับจาก register แรกที่ poll: Float แสดงที่แถว 0, 2, 4... ส่วนแถว 1, 3, 5... ที่ถูกค่าข้างบนใช้อยู่ **เว้นว่าง** เหมือนโปรแกรม Modbus master ทั่วไป (Double แสดงทุก 4 แถว) ชนิด 1 register แสดงทุกแถวเหมือนเดิม ค่าที่ได้เท่ากับตาราง Display ปกติ ถ้าค่า 32 บิตของอุปกรณ์เริ่มที่ register คู่ที่สอง ให้เลื่อนจังหวะ (align) แล้วค่าจะมาอยู่ถูกแถว ช่องว่างแก้ไขไม่ได้ (แก้ที่แถวที่เริ่มค่า) และถ้า register ที่อ่านมาเหลือไม่พอสำหรับชนิดนั้น แถวสุดท้ายก็เว้นว่างด้วย
- แถวที่ register เปลี่ยนค่ากะพริบสีเหลือง ค่าจากรอบที่ล้มเหลวหรือหลังตัดการเชื่อมต่อเป็นสีเทา เหมือน [[grid]]
- **ดับเบิลคลิก** ช่อง (หรือเลือกแล้วกด Enter/F2) เพื่อแก้ค่า ค่าถูกเขียนตาม **ชนิดของคอลัมน์นั้น** เริ่มที่ address ของแถว ชนิด 1 register ใช้ FC06 ส่วน Long/Float/Double เขียน register ถัดไปด้วยโดยใช้ FC16 กด Esc เพื่อยกเลิก ใช้ได้กับ FC03 เท่านั้น
- คลิกขวาหรือ F4 เปิดตัวตรวจค่า ([[inspector]]) ที่แถวนั้น จำนวน register เริ่มต้นตามคอลัมน์ที่เลือก ปุ่ม Write... (F6) เติม address และชนิดจากช่องที่เลือกให้
- FC01/FC02 (coil, discrete input) เป็นบิตเดี่ยว ไม่มีชนิดข้อมูล ช่องติ๊กจึงถูกปิดและแสดงตารางปกติ
- ไม่ใช้กับ Preset view ([[preset-view]]) ซึ่งแสดงค่าตามชนิดที่ preset กำหนดอยู่แล้ว
- Log, Trend และ Alerts ยังใช้ค่าตามรูปแบบ Display ที่เลือกไว้ เหมือนตอนปิดโหมดนี้
- หน้าต่าง Slave Simulator มีช่องติ๊ก Multi-type view ในแท็บ Data เช่นกัน ([[slave-sim]]) ใช้คอลัมน์ชุดเดียวกับหน้าต่างหลัก

## หน้าต่างเขียนค่า (F6)
<!-- id: write-dialog | category: ฟีเจอร์ในโปรแกรม | keywords: write dialog เขียน f6 fc05 fc06 fc15 fc16 fc22 fc23 ส่งค่า -->
เขียนได้ทุก function: FC05, 06, 15, 16, 22, 23 แต่ละ function แสดงเฉพาะช่องที่ใช้ ช่องเติมค่าจากช่องที่เลือกในตารางให้ ก่อนส่งแสดงสรุปว่าจะเขียนอะไรที่ address ไหน

**ระวัง:** การเขียนเปลี่ยนสถานะของอุปกรณ์จริงทันที โดยเฉพาะไดรฟ์มอเตอร์ วาล์ว หรือค่า calibration ถ้าเขียนแล้วไม่ได้ผล ดู [[trouble-write-fail]]

## ตัวตรวจค่า Value Inspector (F4)
<!-- id: inspector | category: ฟีเจอร์ในโปรแกรม | keywords: inspector ตรวจค่า f4 ตีความ ชนิดข้อมูล float long word order หาชนิด -->
แสดงค่าของ register ที่เลือก (รวม 1, 2 หรือ 4 ตัวติดกัน) ในทุกวิธีตีความพร้อมกัน: 16 บิต (unsigned, signed, hex, binary, บิตที่เป็น 1, float16, BCD, ASCII), 32 บิต (ลำดับ ABCD/CDAB/BADC/DCBA: unsigned, signed, float, เวลา Unix), 64 บิต (unsigned, signed, double)

หน้าต่างตามช่องที่เลือก อัปเดตสดจากการ poll ล่าสุดโดยไม่อ่านเพิ่ม ดับเบิลคลิกแถวเพื่อคัดลอก ปุ่ม "Use as preset point..." สร้างจุดวัดใหม่ใน preset จากแถวที่เลือก ใช้ร่วมกับ [[word-order]]

CLI: `python interpret.py --words 0x4348 0xCCCD` หรืออ่านจากอุปกรณ์ `python interpret.py tcp://host:502 -u 1 -a 0 -n 2`

## Traffic Monitor (F8)
<!-- id: traffic-monitor | category: ฟีเจอร์ในโปรแกรม | keywords: traffic monitor f8 hex frame pdu tx rx err ดูข้อมูลที่ส่ง log สาย -->
แสดงทุกการสื่อสารที่ master ส่งและรับ: เวลา (ถึงมิลลิวินาที), ทิศทาง (**TX** ส่ง, **RX** รับ, **ERR** ผิดพลาด), Slave ID, PDU เป็น hex และคำอธิบาย เช่น `Read Holding Registers addr=0 qty=10`

มีปุ่มหยุดเลื่อน (ยังเก็บข้อมูลต่อ), ล้าง, กรองทิศทาง, คัดลอก และบันทึกเป็นข้อความ/CSV หน้าต่างแสดงล่าสุด 3,000 แถวและเก็บในหน่วยความจำได้ถึง 20,000 รายการ (บัฟเฟอร์ภายในของตัว master เก็บ 500 รายการ) ใช้ไล่หาสาเหตุเมื่ออุปกรณ์ไม่ตอบ เทียบ PDU กับตัวอย่างในคู่มืออุปกรณ์ได้โดยตรง

## Preset view (F7)
<!-- id: preset-view | category: ฟีเจอร์ในโปรแกรม | keywords: preset view f7 อุปกรณ์ แผนที่ register ชื่อ หน่วย verified unverified -->
เลือก preset ของอุปกรณ์แล้วตารางเปลี่ยนเป็นแบบมีชื่อ ค่าที่ปรับ scale พร้อมหน่วย และข้อความ enum (เช่น 1 = Run)

- ป้าย **VERIFIED / UNVERIFIED** และแถบเหลืองเตือนเมื่อยังไม่ยืนยัน preset ในไลบรารีทั้งหมดเขียนจากคู่มือ ยังไม่ผ่านการทดสอบกับอุปกรณ์จริง ให้เทียบค่ากับหน้าจอเครื่องก่อนเชื่อ
- **Apply preset connection settings:** นำค่า baud/parity/ID ของ preset มาใช้ (ต้องกดเอง)
- **Try other base:** อ่านชั่วคราวโดยสลับ address base 0↔1 เพื่อเทียบ ถ้าตรงกดเก็บเป็นสำเนาของคุณ
- แก้ค่าที่เขียนได้ด้วยดับเบิลคลิก ตรวจช่วงค่าก่อนส่ง ครั้งแรกของ preset ที่ยังไม่ยืนยันจะถามยืนยัน
- จุดแบบ "w" (เขียนอย่างเดียว) แสดงเป็นปุ่ม ▶ Send...

รายละเอียดของไฟล์ preset: [[preset-schema]] แก้ preset ในโปรแกรม: [[preset-editor]]

## ตัวแก้ Preset
<!-- id: preset-editor | category: ฟีเจอร์ในโปรแกรม | keywords: preset editor แก้ preset เพิ่มจุด csv import verified shift address -->
แก้ทุกฟิลด์ของจุดวัด (ชื่อ, address, fc, type, word order, byte swap, scale, offset, หน่วย, access, ช่วงค่า, กลุ่ม, enum) เพิ่ม/ทำซ้ำ/ลบ/เรียงลำดับ ตรวจความถูกต้องก่อนบันทึก นำเข้าจาก CSV ได้

- **Shift all +1/−1:** เลื่อน address ของทุกจุด ถ้าติ๊ก "keep protocol addresses" จะปรับ address_base ให้ด้วย เพื่อให้ address ที่ส่งจริงบนสายไม่เปลี่ยน แก้ปัญหาฐาน ([[address-bases]])
- **Mark as verified:** ติ๊กหลังเทียบกับอุปกรณ์จริงเท่านั้น ต้องใส่หมายเหตุว่าใครตรวจกับรุ่นไหนเมื่อไร
- บันทึกลงโฟลเดอร์ library จะถามก่อนเขียนทับ ค่าเริ่มต้นเป็นสำเนา `_custom` ในโฟลเดอร์ `presets`

## กราฟ Trend (F10)
<!-- id: trend | category: ฟีเจอร์ในโปรแกรม | keywords: trend graph กราฟ f10 แนวโน้ม plot export csv -->
วาดค่าตามเวลา เลือกได้สูงสุด 8 เส้น (ตามชื่อจุดใน preset หรือ address) แกน Y ร่วมหรือแยกเส้น เคอร์เซอร์อ่านค่า ณ เวลาหนึ่ง หยุด/เล่นต่อ เลือกช่วงเวลา (1 นาที, 10 นาที, 1 ชั่วโมง, ทั้งหมด) การ poll ที่ล้มเหลวแสดงเป็นช่องว่างในเส้น ส่งออก CSV ได้ ข้อมูลเก็บในหน่วยความจำแบบจำกัดขนาด

## ระบบแจ้งเตือน (Alerts)
<!-- id: alerts | category: ฟีเจอร์ในโปรแกรม | keywords: alerts alarm แจ้งเตือน เกิน ต่ำกว่า hysteresis threshold เงียบ stuck acknowledge -->
กฎต่อจุดวัด: **above** (เกิน), **below** (ต่ำกว่า), **outside** (นอกช่วง), **equals**, **changed**, **no data for N s** (อุปกรณ์เงียบ), **stuck for N s** (ค่าค้าง)

- **Min duration (for_s):** ต้องเกิดต่อเนื่องกี่วินาทีจึงเตือน กันสัญญาณกระตุก
- **Hysteresis:** ค่าต้องกลับเข้าเขตปลอดภัยเกินระยะนี้จึงถือว่าปกติ กันการเด้งไปมา
- สถานะ: ปกติ → เตือน → รับทราบ (Acknowledge) → ปกติ มีบันทึกเหตุการณ์ ส่งออก CSV ได้ และแถบแดงเมื่อมีเตือนที่ยังไม่รับทราบ
- กฎกำหนดใน preset (`alarms`) หรือแก้ใน GUI เสียงเตือนปิดไว้เป็นค่าเริ่มต้น

## หลายอุปกรณ์ (Devices, F11)
<!-- id: devices | category: ฟีเจอร์ในโปรแกรม | keywords: devices หลายอุปกรณ์ f11 multi poll bus rs485 หลายตัว พร้อมกัน -->
poll หลายอุปกรณ์พร้อมกัน แต่ละตัวมีชื่อ การเชื่อมต่อ preset Slave ID และ scan rate

- อุปกรณ์ที่ใช้ **สาย RS-485 เดียวกัน** ใช้พอร์ตร่วมกัน และถูก poll **ทีละตัว** (ไม่ชนกัน) โดยเว้นช่วงสั้น ๆ ระหว่างกัน
- คนละสายหรือคนละ TCP poll พร้อมกัน
- อุปกรณ์ตัวหนึ่งดับหรือไม่ตอบ ไม่ทำให้ตัวอื่นช้าเกินเวลา timeout ของมัน
- ตารางภาพรวมแสดงสถานะ (ok/error/stale) เวลาล่าสุด ตัวนับ และค่าสรุป
- ตั้งให้ log แยกไฟล์ต่ออุปกรณ์ได้ ([[logging]])
- หน้าต่างเป็นแท็บ: **Overview** (ตารางนี้) **Cycle** **Calculator** และ **แท็บละอุปกรณ์** ที่แสดงค่าทั้งหมดล่าสุด ปุ่ม **Scan & add...** หาอุปกรณ์บนสายแล้วเพิ่มให้: ดู [[devices-tabs]]
- **Scan mode:** Independent (แต่ละตัวอ่านตาม scan rate ของตัวเอง ค่าเริ่มต้น) หรือ **PLC cycle** (อ่านทุกตัวบนสายวนเป็นรอบแบบ PLC พร้อมสถิติเวลา) ดู [[plc-cycle]]
- ปุ่ม **Bus map...** วาดว่าอุปกรณ์ต่ออยู่ตรงไหนบนสาย RS-485 ความยาวสาย terminator และดูภาพคำขอ/คำตอบวิ่ง ดู [[bus-map]]
- แท็บ poll ในหน้าต่างหลัก (Poll 2, Poll 3...) ก็เป็นอุปกรณ์ในรายการนี้ด้วย: ดู [[poll-tabs]]

## แท็บต่ออุปกรณ์ และ Scan & add
<!-- id: devices-tabs | category: ฟีเจอร์ในโปรแกรม | keywords: devices tabs แท็บ อุปกรณ์ scan add สแกน เพิ่มอุปกรณ์ หา slave id ค้นหา identify fc43 preset อัตโนมัติ tick ติ๊ก -->
หน้าต่าง Devices (F11) มีแท็บ **Overview** และ **แท็บละหนึ่งอุปกรณ์** ชื่อแท็บมีจุดสีบอกสถานะ: เขียว = ok, แดง = error, ส้ม = ไม่มีคำตอบนานแล้ว (stale), เทา = หยุดอยู่

แท็บของอุปกรณ์แสดง:
- หัว: การเชื่อมต่อ, Slave ID, สิ่งที่อ่าน, สถานะ, เวลาอัปเดตล่าสุด, ตัวนับ OK / error และข้อความ error ล่าสุด
- ปุ่ม **Start/Stop** (เฉพาะตัวนี้), **Edit...**, **Show in main window** (แสดงในหน้าต่าง Trend และเลือกใน Traffic / Alerts)
- มี preset: ตาราง **Point, Value, Unit, Raw, Status** ค่าที่ scale แล้วและชื่อ enum มาจากผลการอ่านรอบเดียวกับ Overview (ไม่อ่านซ้ำ) จุดที่อ่านไม่ได้เป็นแถวแดงพร้อมเหตุผล
- ไม่มี preset: ตาราง address / ค่า ของช่วง register ที่ตั้งไว้ แบบ multi-type ([[multi-view]]) หลายชนิดข้อมูลพร้อมกัน
- แท็บนี้เขียนค่าไม่ได้ (ใช้หน้าต่างหลัก F6 หรือ preset view)

แท็บถูกสร้าง/ลบ/เปลี่ยนชื่อตามรายการอุปกรณ์เอง (Add, Edit, Remove, Scan & add, เปิด workspace)

**Scan & add...** (ปุ่มใน Overview):
1. เลือกการเชื่อมต่อ (ค่าเริ่มต้น = การเชื่อมต่อของหน้าต่างหลัก) ช่วง Slave ID (เริ่ม 1 ถึง 32) timeout (300 ms ก็พอ: ID ที่ไม่มีอุปกรณ์จะเสียเวลาเท่านี้ต่อตัว) และ function ที่ใช้ทดลองอ่าน
2. กด **Scan** สแกนทำงานเบื้องหลัง มีแถบความคืบหน้าและ **Cancel scan** คำตอบ exception ก็นับว่ามีอุปกรณ์ ([[scanner]])
3. ตัวที่ตอบถูกลองถามชื่อรุ่นด้วย FC43 / FC17 ([[fc43]]) ถ้าตอบ จะแนะนำ preset ในคลังที่ชื่อตรงกันที่สุด เปลี่ยนได้ในช่อง **Preset** (หรือ none = อ่าน holding 0..9)
4. ติ๊กช่อง **Add** (คลิก หรือ Space; Select all / Select none) แก้ **Name** ได้ แล้วกด **Add selected** จะได้อุปกรณ์และแท็บทันที (ยังไม่ start)

ตัวที่มีอยู่แล้ว (การเชื่อมต่อเดียวกันและ ID เดียวกัน) ขึ้นว่า **already added** และติ๊กไม่ได้ สแกนซ้ำจึงไม่เพิ่มซ้ำ ถ้าเปิดพอร์ตไม่ได้หรือไม่มีใครตอบ จะบอกในบรรทัดสถานะ (ตรวจสาย baud / parity: [[trouble-no-response]])

preset จากคลังยังไม่ได้ยืนยันกับเครื่องจริง เทียบค่ากับหน้าจออุปกรณ์ก่อนใช้งาน

## โหมด PLC cycle และการออกแบบบัส
<!-- id: plc-cycle | category: ฟีเจอร์ในโปรแกรม | keywords: plc cycle scan cycle รอบ เวลารอบ cycle time jitter overrun timeout line busy ออกแบบบัส bus design calculator คำนวณ baud response delay rs485 รอบการอ่าน -->
**Scan mode** ในแท็บ Overview ของหน้าต่าง Devices:
- **Independent (per-device scan rate):** แต่ละอุปกรณ์อ่านตาม scan rate ของตัวเอง (แบบเดิม)
- **PLC cycle:** แต่ละ **บัส** (หนึ่งพอร์ต RS-485 หรือหนึ่ง TCP host:port) อ่านอุปกรณ์ที่เปิดใช้ทุกตัว **เรียงกันทีละตัว** (ทุก block ของ preset) จบแล้วเริ่มรอบใหม่ เหมือน task ของ PLC ระหว่างคำขอแต่ละครั้งเว้น **Bus gap**
- **Cycle time target (ms):** ว่าง = เริ่มรอบใหม่ทันที ใส่ตัวเลข = รอบคงที่: ถ้าเสร็จเร็วจะรอส่วนที่เหลือ ถ้าเกินนับเป็น **overrun**

แท็บ **Cycle** (วัดด้วยนาฬิกาความละเอียดสูง):

| ค่า | ความหมาย |
|---|---|
| Last / Avg / Min / Max ms | เวลาทำงานของหนึ่งรอบ (อ่านทุกตัวบนบัสนั้น รวม gap) ไม่รวมเวลารอให้ครบ target |
| Jitter ms | Max - Min ยิ่งน้อยยิ่งสม่ำเสมอ |
| Cycles/s | จำนวนรอบต่อวินาทีจริง (รวมเวลารอ target) |
| Target / Overruns | เป้ารอบ และจำนวนรอบที่ใช้เวลาเกินเป้า |
| Timeouts / Errors | คำขอที่หมดเวลา / ผิดพลาดทั้งหมด (รวมเปิดพอร์ตไม่ได้) |
| Line busy | bytes x bits ต่อตัวอักษร / baud เทียบกับเวลารอบ (% ที่สายมีข้อมูลวิ่ง) เฉพาะ serial; TCP = n/a |
| Requests / cycle | จำนวนคำขอของอุปกรณ์นั้นต่อรอบ (preset ที่มีหลาย block = หลายคำขอ) |
| ms / cycle | เวลาเฉลี่ยของอุปกรณ์นั้นในหนึ่งรอบ |
| Avg / Worst response ms | เวลาตั้งแต่ส่งคำขอจนได้คำตอบ เฉลี่ยและแย่สุด |

กราฟด้านล่างแสดงเวลารอบ ~120 รอบล่าสุด เส้นประ = target ปุ่ม **Reset statistics** เริ่มนับใหม่ **Copy report** คัดลอกรายงานเป็นข้อความ (มีค่าประมาณการด้วย)

แท็บ **Calculator** (ใช้ได้โดยไม่ต้อง poll): ใส่ชนิดสาย RTU/ASCII/TCP, baud, parity, stop bits, master gap, timeout, USB adapter latency, response delay ของอุปกรณ์, retries และ target รายการอุปกรณ์มาจากที่ตั้งไว้ (block ของ preset หรือช่วง register) แก้ response delay และ Online ต่อตัวได้ ผลที่ได้: เวลารอบรวม, ต่ออุปกรณ์, cycles/s, line busy, ตาราง baud what-if และคำแนะนำ ปุ่ม **Compare with measured** เทียบค่าประมาณ (ใช้การเชื่อมต่อจริงของแต่ละบัสและ Bus gap) กับค่าเฉลี่ยที่วัดได้ในแท็บ Cycle เป็น %

**ออกแบบบัสจากตัวเลขเหล่านี้:**
1. ใส่อุปกรณ์ทั้งหมดที่จะต่อ แล้วดู Calculator: เวลารอบเกินที่ต้องการไหม
2. **Line busy ต่ำ** (ต่ำกว่า ~35 %): เวลาหมดไปกับการรอ (response delay, gap, USB latency) เพิ่ม baud ช่วยน้อย ลด gap / latency หรือแบ่งอุปกรณ์ไปอีกพอร์ต **Line busy สูง:** เพิ่ม baud ถ้าทุกตัวรองรับ
3. อุปกรณ์ที่ **ไม่ตอบ** เสียเวลาเท่า timeout ทุกรอบ: เอาออกหรือลด timeout
4. preset ที่มีหลาย block = หลายคำขอ: จัดจุดที่อยู่ใกล้กันให้อยู่ block เดียว
5. เปิดโหมด PLC cycle กับของจริงหรือ simulator แล้ว **Compare with measured** ถ้าวัดได้ช้ากว่ามาก ให้แก้ response delay ใน Calculator ให้ตรง (ดู Worst response) แล้วออกแบบต่อจากตัวเลขที่ตรงกับจริง
6. ตั้ง target ให้มากกว่า Max ที่วัดได้พอสมควร (เผื่อ jitter และ retry) แล้วดูว่า Overruns เป็น 0

ทดลองโดยไม่มีฮาร์ดแวร์: `python mbtool.py vcom --baud 38400 --bits 10` (จำลองความเร็วสาย) และ `python mbtool.py sim --serial socket://127.0.0.1:7000 -u 1 --baud 38400 --delay 10` (หน่วงคำตอบ 10 ms) หรือช่อง **Response delay (ms)** ใน Slave Simulator ดู [[vcom]] และ [[slave-sim]]

อยากเห็นว่าอุปกรณ์อยู่ตรงไหนบนสาย ความยาวสายเท่าไร และคำขอ/คำตอบวิ่งอย่างไร ดู [[bus-map]] (Ctrl+M)

วัดเวลาตอบจริงและหา timeout / gap ที่เหมาะกับสายเส้นนี้ ดู [[bus-health]]

## ทดสอบสุขภาพบัส (Health test) และชนิดของ error
<!-- id: bus-health | category: ฟีเจอร์ในโปรแกรม | keywords: health test สุขภาพ บัส ทดสอบสาย timeout gap แนะนำ response time เวลาตอบ p95 crc error ชนิด error error types line quality คุณภาพสาย sweep -->
แท็บ **Health test** ในหน้าต่าง Devices ทดสอบอุปกรณ์ทุกตัวบนบัสที่เลือก (หนึ่งพอร์ต COM หรือหนึ่ง TCP host:port) ระหว่างทดสอบ โปรแกรมจะหยุด poll อุปกรณ์บนบัสนั้นชั่วคราว แล้วเริ่มต่อให้เองเมื่อเสร็จ

1. **วัดเวลาตอบ:** อ่านอุปกรณ์แต่ละตัวตาม **Requests per device** (ค่าเริ่ม 20 ครั้ง) ใช้ **Probe timeout** ยาว (2000 ms) เพื่อให้คำตอบที่ช้าถูกจับเวลาได้ ไม่ถูกตัดทิ้ง preset ใช้ block แรกที่อ่านได้
2. **Gap sweep** (เฉพาะ serial): อ่านทุกตัววนกัน แล้วลด gap ลงเรื่อย ๆ (50, 20, 10, 5, 2, 0 ms) เพื่อดูว่าสายนี้ poll ถี่ได้แค่ไหนโดยไม่มี error

| คอลัมน์ | ความหมาย |
|---|---|
| Grade | good = ตอบครบ เวลาสม่ำเสมอ, warn = มี error บ้าง หรือเวลาแกว่ง หรือใกล้ timeout, bad = error 5 % ขึ้นไป, no answer = ไม่มีคำตอบที่ถูกต้องเลย |
| Avg / p95 / Max ms | เวลาไป-กลับของหนึ่งคำขอ (p95 = 95 % ของคำขอเร็วกว่าค่านี้) |
| Device delay ms | เวลาเฉลี่ยหักเวลาที่เฟรมวิ่งบนสายออกแล้ว = เวลาที่อุปกรณ์ใช้คิดก่อนตอบ |
| Timeout needed | ค่าที่ใช้ได้กับตัวนั้น: คำตอบที่ช้าสุด x 1.5 (อย่างน้อย +50 ms) ปัดขึ้นทีละ 50 ms ต่ำสุด 100 ms |

ปุ่ม **Apply recommended timeout + gap** ตั้ง timeout ของทุกอุปกรณ์บนบัสนี้ และตั้ง Bus gap ตามค่าที่แนะนำ **Use measured delays in Calculator** เอา Device delay ที่วัดได้ไปใส่ในแท็บ Calculator (ตัวที่ไม่ตอบจะถูกตั้งเป็น offline) เพื่อให้ค่าประมาณตรงกับสายจริง ส่วน **Copy report** คัดลอกผลเป็นข้อความ

ไม่ได้ไล่ทดสอบ baud เพราะ baud ตั้งไว้ที่ตัวอุปกรณ์ ถ้า master เปลี่ยน baud เองจะคุยกับอุปกรณ์ไม่ได้เลย ถ้าจะลอง baud อื่น ต้องตั้งที่อุปกรณ์ทุกตัวก่อน แล้วค่อยทดสอบใหม่ ผลทดสอบครั้งล่าสุดจะใส่ในรายงานส่งมอบงานให้เอง ดู [[commission-report]]

**ชนิดของ error** (คอลัมน์ Error types ใน Overview และ Errors by type ในแท็บของอุปกรณ์):

| ย่อ | ชนิด | มักเกิดจาก |
|---|---|---|
| T | Timeout | ไม่ตอบ: ผิด Slave ID / baud / parity, สายขาด, A-B สลับ, ไฟไม่เข้า หรือ timeout สั้นเกินไป |
| C | CRC / LRC | เฟรมเสียระหว่างทาง: terminator, ชีลด์/กราวด์, สายยาวเกินสำหรับ baud, stub ยาว, สัญญาณรบกวน |
| E | Exception | อุปกรณ์ปฏิเสธคำขอ: address / จำนวน / function code ไม่รองรับ (เป็นเรื่องการตั้งค่า ไม่ใช่สาย) |
| F | Bad frame | คำตอบไม่ครบหรือรูปแบบผิด: สัญญาณรบกวน หรือ USB adapter ตัดเฟรม |
| W | Wrong ID | ตอบมาจาก Slave ID อื่น: มีสองตัวใช้ ID ซ้ำกัน หรือคำตอบที่มาช้าหลัง timeout |
| L | No connection | เปิดพอร์ตหรือเชื่อมต่อ TCP ไม่ได้ |
| O | Other | อื่น ๆ |

คอลัมน์ **Resp. ms avg/max** เป็นเวลาไป-กลับของหนึ่งคำขอ นับตั้งแต่เริ่ม poll หรือตั้งแต่กด **Reset counters** ในแท็บของอุปกรณ์ ส่วน **Line quality** คือสัดส่วนคำขอที่ผิดพลาด: good = 0 %, fair ต่ำกว่า 1 %, poor ต่ำกว่า 5 %, bad ตั้งแต่ 5 % ขึ้นไป

## ส่งข้อมูลออก MQTT / ฐานข้อมูล (Data export)
<!-- id: data-export | category: ฟีเจอร์ในโปรแกรม | keywords: export ส่งข้อมูล mqtt broker mosquitto node-red home assistant sqlite database ฐานข้อมูล grafana scada iot cloud topic payload json retain tls -->
เมนู **Tools > Data export (MQTT / database)...** ส่งค่าที่อ่านได้ทุกครั้งของอุปกรณ์ในหน้าต่าง Devices (F11) ออกไปยัง MQTT broker หรือไฟล์ฐานข้อมูล SQLite หรือทั้งสองแบบพร้อมกัน การส่งทำในเบื้องหลัง broker ที่ช้าหรือดิสก์ที่ช้าจึงไม่ทำให้การอ่านอุปกรณ์ช้าลง

**MQTT:** ใส่ Broker host, Port (1883 หรือ 8883 ถ้าใช้ TLS), User name / Password (ถ้า broker ต้องใช้), Topic prefix เช่น `plant1/line3` แล้วกด **Test connection** ก่อน โปรแกรมจะส่งข้อความทดสอบไปที่ `<prefix>/_test`

| Payload | ข้อความที่ส่ง |
|---|---|
| one JSON per device | topic `<prefix>/<device>` ข้อมูล `{"ts": "...", "ok": true, "values": {"Voltage": 230.1, ...}}` ถ้าอ่านไม่ได้จะส่ง `"ok": false` พร้อม `"error"` |
| one topic per point | `<prefix>/<device>/<point>` = ค่า และ `<prefix>/<device>/status` = สถานะ |

- **Retain:** broker เก็บข้อความล่าสุดของแต่ละ topic ไว้ให้ client ที่เพิ่ง subscribe เข้ามาทีหลัง
- **Min. interval (s):** ส่งแต่ละอุปกรณ์ไม่ถี่กว่าค่านี้ (0 = ส่งทุกครั้งที่อ่าน) ช่วยลดปริมาณข้อมูลไป cloud
- ใช้ QoS 0 ถ้า broker หลุด โปรแกรมจะเก็บข้อความรอไว้ (สูงสุด 5000 รายการ ถ้าเกินจะทิ้งรายการเก่าสุดและนับเป็น dropped) แล้วต่อใหม่เองโดยรอนานขึ้นทีละขั้นจนถึง 30 วินาที
- **Password ไม่ถูกบันทึกลงไฟล์ใด ๆ** (เหมือน token ของ AI) เปิดโปรแกรมใหม่ต้องใส่อีกครั้ง
- ชื่ออุปกรณ์และจุดที่มี `/ + #` จะถูกแทนด้วย `_` ใน topic

**SQLite:** เลือกไฟล์ `.db` (สร้างให้ถ้ายังไม่มี) ทุกค่าเป็นหนึ่งแถวในตาราง `readings` (ts = เวลาแบบตัวเลข, time = เวลาแบบข้อความ ISO, device, point, value = ตัวเลข, text = ข้อความ, ok = 1/0) การอ่านที่ไม่สำเร็จเป็นแถว ok = 0 และ text = ข้อความ error เปิดไฟล์ได้ด้วย DB Browser for SQLite, Python, Grafana (SQLite plugin) หรือ Excel ผ่าน ODBC

จุดของอุปกรณ์ที่ใช้ preset ใช้ชื่อจุดตาม preset ส่วนอุปกรณ์ที่อ่านเป็นช่วง register จะใช้ชื่อ address ตามฐานที่เลือก (เช่น `40001`) ข้อมูลจาก Poll 1 ของหน้าต่างหลักไม่ถูกส่ง ถ้าต้องการให้เพิ่มเป็นอุปกรณ์ใน Devices ฐานข้อมูลอื่น เช่น SQL Server, PostgreSQL, InfluxDB ยังไม่รองรับโดยตรง ให้ใช้ MQTT ต่อไปยังระบบเหล่านั้นแทน (เช่น Node-RED หรือ Telegraf)

## รายงานส่งมอบงาน (Commissioning report)
<!-- id: commission-report | category: ฟีเจอร์ในโปรแกรม | keywords: report รายงาน ส่งมอบ commissioning handover pdf html พิมพ์ print ลงนาม sign off ลูกค้า เอกสาร -->
เมนู **File > Commissioning report...** หรือปุ่ม **Report...** ในหน้าต่าง Devices ทำรายงานหน้าเดียวสำหรับส่งมอบงานหรือเก็บเป็นหลักฐานหน้างาน ส่งค่าออกต่อเนื่องไประบบอื่น ดู [[data-export]]

กรอก **Project, Site, Customer, Commissioned by** และ **Notes** (โปรแกรมจำไว้ใช้ครั้งหน้า) เลือกภาษา **English** หรือ **ไทย** แล้วกด **Save report...** จะได้ไฟล์ HTML และถ้าติ๊ก **Also save a PDF** จะได้ PDF ด้วย (ใช้ Microsoft Edge พิมพ์ ซึ่งมีอยู่ใน Windows 10/11 ทุกเครื่อง) ส่วนปุ่ม **Preview** เปิดดูในเบราว์เซอร์ก่อนบันทึก

ในรายงานมี:
- **สรุปผล:** ผ่าน (อุปกรณ์ที่เปิดใช้ตอบครบทุกตัว และ error ต่ำกว่า 1 %) หรือ ต้องตรวจสอบ
- **การตั้งค่าการอ่าน และบัสแต่ละเส้น:** การเชื่อมต่อ, เวลารอบที่วัดได้ในโหมด PLC cycle เทียบกับค่าประมาณ, overruns, line busy
- **อุปกรณ์ทุกตัว:** สถานะ, OK และ error, อัตรา error, ชนิด error, เวลาตอบ (เฉลี่ย / p95 / สูงสุด), error ล่าสุด
- **ค่าที่อ่านได้ ณ ตอนทำรายงาน** (16 ค่าแรกต่ออุปกรณ์)
- **ผลทดสอบสุขภาพบัสครั้งล่าสุด** ([[bus-health]]) พร้อมค่าที่แนะนำและข้อสังเกต
- **แผนผังบัส** ([[bus-map]]): ภาพ, ความยาวสาย, baud ที่แนะนำ, unit load และข้อสังเกตการเดินสาย
- **ช่องลงนาม** ผู้ทดสอบและผู้รับมอบ

รายงานครอบคลุมเฉพาะอุปกรณ์ในหน้าต่าง Devices (รวม poll tab) ไม่รวม Poll 1 ของหน้าต่างหลัก ถ้าอยากให้ตัวเลขน่าเชื่อถือ ให้ poll ไว้สักพัก แล้วทดสอบสุขภาพบัสก่อนทำรายงาน

## แผนผังบัส RS-485 (Bus map, Ctrl+M)
<!-- id: bus-map | category: ฟีเจอร์ในโปรแกรม | keywords: bus map แผนผัง บัส สาย rs485 ความยาวสาย cable length stub terminator 120 ohm bias ต่อสาย daisy chain topology animation ภาพเคลื่อนไหว สัญญาณ วิ่ง propagation delay unit load แรงดันตก -->
เปิดจากเมนู **Tools > Bus map...** (Ctrl+M) หรือปุ่ม **Bus map...** ในหน้าต่าง Devices เป็นหน้าที่ **วาด** ว่าอุปกรณ์แต่ละตัวต่ออยู่ตรงไหนบนสาย RS-485 แล้ว **จำลอง** ให้เห็นว่าคำขอจาก master (โปรแกรมนี้) วิ่งไปหา slave และคำตอบวิ่งกลับอย่างไร

**โปรแกรมมองไม่เห็นสายจริง:** Modbus ไม่ได้บอกระยะทางหรือตำแหน่ง ผู้ใช้จึงต้องเป็นคนวาดแผนผังเอง ถ้าใส่ลำดับและความยาวถูก โปรแกรมจะคำนวณต่อให้ได้อีกหลายอย่าง

**วิธีใส่แผนผัง:**
1. กด **Import from Devices** เพื่อสร้างอุปกรณ์จากที่ตั้งไว้ใน Devices (เฉพาะตัวที่ใช้ RS-485 เรียงตาม Slave ID) หรือ **Add device** เพิ่มเอง ช่อง **Not on the map yet** แสดงอุปกรณ์ที่ตั้งไว้แต่ยังไม่อยู่บนแผนผัง (กด **Add to map**)
2. เรียงแถวด้วย **Move up / Move down** ให้ตรงกับลำดับจริงบนสาย แถว 1 = ใกล้ master ที่สุด
3. ดับเบิลคลิกช่องในตารางเพื่อแก้ (Enter = ใช้ค่า, Esc = ยกเลิก): **Segment (m)** = ความยาวสายจากตัวก่อนหน้า (แถว 1 = จาก master), **Stub (m)** = สายแยกจาก trunk ไปถึงตัวอุปกรณ์ (0 = ต่อแบบ daisy chain เข้า-ออกที่ตัวอุปกรณ์), **Unit load**, **Supply (mA)** (อุปกรณ์ที่กินไฟจากสายเดียวกัน) คลิกช่อง **Terminator** เพื่อสลับว่ามี 120 Ω ที่ตัวนั้น ค่าที่ผิด (ติดลบ, Slave ID ซ้ำ) จะไม่ถูกใช้และแจ้งในบรรทัดสถานะ
4. ด้านบนเลือก **Cable** (ค่าทั่วไปของสาย; **Custom** ใส่ค่าจาก datasheet: vf, Ω/km, pF/m, dB/100m) **Baud** (ค่าเริ่มต้นของแผนผังใหม่ = baud ของการเชื่อมต่อหน้าต่างหลัก) **Master at one end** **120 Ω at master end / far end** **Bias** **Supply V** และ **Rise time (ns)** ของ transceiver ทุกการเปลี่ยนแปลงคำนวณใหม่และวาดใหม่ทันที

**อ่านภาพ:**
- กล่อง **MASTER** อยู่ซ้ายสุด (หรือเกาะสายด้วย stub ถ้าไม่ได้ติ๊ก Master at one end) เส้นหนาแนวนอนคือ **trunk** กล่องที่ห้อยลงมาคืออุปกรณ์ เรียงตามลำดับในตาราง
- ตัวเลขบน trunk = ความยาวแต่ละช่วง ตัวเลขข้างเส้นห้อย = ความยาว stub เส้นวงเล็บด้านล่าง = ความยาว trunk ทั้งหมดและระยะของตัวที่ไกลที่สุด
- สัญลักษณ์ซิกแซก **120 Ω** = terminator ที่ปลายสาย (open end = ไม่มี) ป้าย **bias** = มี bias ที่ master
- สีกล่อง: เขียว = poll อยู่และตอบปกติ, แดง = error, ส้ม = ไม่มีคำตอบนาน (stale), เทา = หยุดอยู่ (ชื่อตรงกับอุปกรณ์ใน Devices), ขาว = ไม่ได้อยู่ใน Devices กรอบน้ำเงิน = ตัวที่เลือก
- ภาพ **ไม่ได้ย่อตามสเกล** ระยะห่างของกล่องเท่ากันเพื่อให้อ่านง่าย ถ้ามีหลายตัวเลื่อนซ้ายขวาได้ หรือติ๊ก **Fit to width**

**ภาพเคลื่อนไหว:** กด **Play** เลือกอุปกรณ์ที่จะถาม (หรือ **All in turn** ถามทีละตัวเหมือนรอบ scan) FC, จำนวน, **Delay ms** (เวลาที่อุปกรณ์ "คิด" ก่อนตอบ) parity และ stop bits ลำดับที่เห็น: สายว่าง t3.5 → **กล่องคำขอสีน้ำเงิน** ออกจาก master วิ่งผ่านทุกตัว (จุดต่อทุกตัวกะพริบเพราะทุกตัวได้ยิน แต่ตัวที่ถูกเรียกเท่านั้นที่ไฮไลต์) → อุปกรณ์คิดตามเวลา delay → **กล่องคำตอบสีเขียว** วิ่งกลับมาที่ master (ตัวอื่นเงียบ) → master กะพริบ แล้วต่อด้วยตัวถัดไป
- สเกลเวลา: **1 วินาทีบนจอ = 50 ms บนสาย ที่ 1x** (ช่วงที่สั้นมากถูกยืดให้เห็นได้) แถบ timeline ใต้ภาพแสดงสัดส่วนจริงเป็น ms: t3.5 | request | device delay | response | gap/usb และเวลารวม
- **Cycle time for all devices on the map** = เวลารอบโดยประมาณถ้า poll ทุกตัวบนแผนผัง (buscalc) อุปกรณ์ที่ตั้งไว้ใน Devices ใช้ block ของ preset / ช่วง register และ response delay ของตัวเองใน Calculator ลองเปลี่ยน baud แล้วดูว่ารอบเปลี่ยนเท่าไร
- **Follow real traffic:** ระหว่างที่หน้าต่างหลักหรือ Devices กำลัง poll จะแสดงคำขอ/คำตอบจริงของอุปกรณ์ที่อยู่บนแผนผัง (อ่านจากบันทึก traffic เท่านั้น ไม่เปลี่ยนการทำงานของโปรโตคอล) ถ้าเกิดเร็วกว่าที่วาดทัน เหตุการณ์ที่เก่ากว่า ~1 วินาทีจะถูกข้ามเพื่อไม่ให้ภาพช้ากว่าจริง

**สิ่งที่คำนวณ (กล่อง Results):** ข้อตรวจสอบ (แดง = error, ส้ม = warn, เทา = info) ความยาว trunk / stub / ตัวที่ไกลที่สุด ระยะและเวลาเดินทางของสัญญาณไปแต่ละตัว (us) baud สูงสุดที่แนะนำสำหรับความยาวนี้เทียบกับที่เลือก ความยาววิกฤต (critical length) และสายนับว่า "ยาวทางไฟฟ้า" หรือไม่ (ต้อง terminate) ความยาว stub ที่ยอมได้ ค่าความจุ ความต้านทานลูป การลดทอน unit load รวม (เทียบ 32) และแรงดันต่ำสุดเมื่อมีอุปกรณ์กินไฟจากสาย ปุ่ม **Copy report** คัดลอกรายงานเป็นข้อความ

**ทำไมระยะทางไม่ทำให้ Modbus ช้า:** ที่ 9600 baud หนึ่งบิตยาวราว 20 กว่ากิโลเมตรของสาย สัญญาณจึงถึงทุกตัวแทบพร้อมกัน (หลักไมโครวินาที) สิ่งที่กินเวลาจริงคือเวลาส่งเฟรม การคิดของอุปกรณ์ gap และ USB latency ([[plc-cycle]]) ส่วนความยาวสายมีผลต่อ **ความเชื่อถือได้**: baud ที่ใช้ได้ การสะท้อน (terminator) stub และแรงดันตก ดู [[rs485-wiring]] และ [[serial-settings]]

ตัวเลขทั้งหมดเป็น **ค่าประมาณจากกฎทั่วไป** และค่าสายแบบทั่วไป ใส่ค่าจาก datasheet ของสายจริงในโหมด Custom และทดสอบกับของจริงเสมอ

**ไฟล์:** แผนผังถูกเก็บในค่าตั้งของโปรแกรมและใน workspace (.mbw) ข้างรายการอุปกรณ์ ([[workspace]]) เมนู **Map > Save map as JSON... / Load map from JSON...** เก็บ/เปิดเป็นไฟล์แยก และ `python mbtool.py busmap map.json` พิมพ์รายงานเดียวกันจาก command line

## บันทึก log เป็น CSV
<!-- id: logging | category: ฟีเจอร์ในโปรแกรม | keywords: log logging csv บันทึก ctrl+l ตัดไฟล์ rotation excel ตัวคั่น utf-8 bom -->
กด **Ctrl+L** เริ่ม/หยุด บันทึกหนึ่งแถวต่อการ poll คอลัมน์แรกเป็นเวลา poll ที่ล้มเหลวเป็นแถว `ERROR`

ตัวเลือก (Log options...):
- **ตัดไฟล์:** ไม่ตัด / รายวัน (`ชื่อ_2026-11-03.csv`) / ตามขนาด (`ชื่อ_วันที่_001.csv`)
- **เก็บ N ไฟล์ล่าสุด:** ลบไฟล์เก่าของ log นี้เท่านั้น (ปิดไว้ก่อน)
- **ตัวคั่น** (, ; แท็บ |), **ทศนิยม** (จุดหรือจุลภาค), **รูปแบบเวลา** (วันที่เวลา, มีมิลลิวินาที, Unix, เลขวันที่ของ Excel), **UTF-8 มี BOM** เพื่อให้ Excel อ่านภาษาไทยถูก
- แยกไฟล์ต่ออุปกรณ์ในหน้าต่าง Devices

## ไฟล์ Workspace (.mbw)
<!-- id: workspace | category: ฟีเจอร์ในโปรแกรม | keywords: workspace mbw บันทึก เปิด ctrl+s ctrl+o โปรเจกต์ ที่ทำงาน -->
บันทึกสถานะทั้งหมดเป็นไฟล์เดียว: อุปกรณ์ การเชื่อมต่อ preset กฎแจ้งเตือน ซีรีส์ของกราฟ ตัวเลือก log address base และตำแหน่งหน้าต่าง เปิดกลับมาได้ทันที (Ctrl+S / Ctrl+O, รายการล่าสุด) ถ้า preset หายหรือไม่มีพอร์ตนั้น จะแจ้งรายการปัญหาแทนที่จะ crash ไม่เก็บ token ใด ๆ

## Slave Simulator
<!-- id: slave-sim | category: ฟีเจอร์ในโปรแกรม | keywords: slave sim simulator จำลอง f9 tcp rtu ascii อุปกรณ์จำลอง ทดสอบ -->
จำลองอุปกรณ์ Modbus ใน GUI (F9): เลือก TCP, RTU หรือ ASCII, Slave ID, แก้ค่าในตารางได้ทั้ง 4 พื้นที่ มีตัวนับคำขอ และแท็บ Traffic แสดงคำขอที่ได้รับกับคำตอบที่ส่ง ใช้ทดสอบโปรแกรมฝั่ง master ของคุณ

**Response delay (ms):** simulator รอเท่านี้ก่อนตอบทุกครั้ง เหมือนอุปกรณ์จริงที่ต้องใช้เวลาคิด (ปกติ 5-50 ms) มีผลทันทีแม้กำลังทำงาน ใช้คู่กับโหมด PLC cycle เพื่อวัดเวลารอบที่สมจริง ([[plc-cycle]])

CLI: `python mbtool.py sim --port 5020 [--preset ไฟล์.json] [--signals random|loop|sine|profile] [--serial COM4 --mode rtu] [--delay 10]` ดู [[vcom]] และทำให้ค่าขยับได้: [[sim-signals]] ทำให้ตอบผิดพลาดโดยตั้งใจ: [[sim-faults]]

## จำลองความผิดพลาด (แท็บ Faults ใน Slave Sim)
<!-- id: sim-faults | category: ฟีเจอร์ในโปรแกรม | keywords: faults fault injection จำลอง ความผิดพลาด error ไม่ตอบ ตอบช้า crc เสีย exception garbage wrong id duplicate id ตัดการเชื่อมต่อ ทดสอบ plc scada master รับมือ -->
แท็บ **Faults** ในหน้าต่าง Slave Sim (F9) ทำให้ slave จำลองตอบผิดพลาดโดยตั้งใจ เพื่อดูว่า master, PLC หรือ SCADA ของคุณรับมือได้ไหม เช่น แสดง error ถูกต้องไหม retry ไหม ค้างหรือเปล่า และกลับมาเองเมื่อสายดีหรือไม่

ติ๊ก **Inject faults** แล้วใส่ **% of requests** ของแต่ละแบบ (0-100) มีผลทันทีแม้ slave กำลังทำงาน คอลัมน์ **Injected** นับว่าเกิดไปแล้วกี่ครั้ง โปรแกรมไม่บันทึกค่าเหล่านี้: เปิดหน้าต่างใหม่จะกลับมาปิดเสมอ

| แบบ | ผลที่ master เห็น |
|---|---|
| No reply | timeout |
| Slow answer | ตอบช้าตาม **Slow answer delay** ถ้าช้ากว่า timeout ของ master จะเห็นเป็น timeout (บน RTU คำตอบที่มาช้าอาจไปปนกับคำขอถัดไป) |
| Exception | exception ตาม **Exception code** ที่เลือก |
| Bad CRC | CRC / LRC ผิด เหมือนสัญญาณรบกวน (เฉพาะ RTU / ASCII) |
| Cut off | คำตอบไม่ครบ |
| Garbage | ได้ไบต์ขยะ |
| Wrong Slave ID | คำตอบมาจาก ID อื่น เหมือนมีสองตัวใช้ ID ซ้ำ |
| Wrong transaction ID | TCP: Transaction ID ไม่ตรง |
| Drop connection | TCP: ตัดการเชื่อมต่อแทนการตอบ |

ปุ่มลัด: **Noisy line** (CRC เสีย 2 %, ตอบไม่ครบ 1 %), **Flaky device** (ไม่ตอบ 5 %), **Slow device** (ตอบช้า 10 %), **Duplicate ID** (ตอบเป็น ID อื่น 20 %), **Unstable network** (ตัดการเชื่อมต่อ 3 %, ไม่ตอบ 3 %) และ **Clear all**

ลองกับ mbtool เอง: เปิด Slave Sim ให้ตอบด้วยความผิดพลาด แล้วอ่านด้วยหน้าต่าง Devices ดูคอลัมน์ Error types หรือกด Health test ([[bus-health]]) จะเห็นชนิด error ตรงกับที่ตั้งไว้

## ค่าจำลองที่ขยับได้ (Signals)
<!-- id: sim-signals | category: ฟีเจอร์ในโปรแกรม | keywords: signals สัญญาณ จำลอง ขยับ สุ่ม random walk loop ramp วนลูป sine พฤติกรรม อุปกรณ์ profile device type sim_pattern ตามพรีเซ็ต -->
Slave จำลองทำให้ค่าเคลื่อนไหวเหมือนอุปกรณ์จริงได้ โดยอ่านรายการจุดจาก preset (แท็บ Signals ในหน้าต่าง Slave Sim, F9) เลือกวิธีขยับได้ 6 แบบ:

| โหมด | ค่าที่ได้ |
|---|---|
| Static | ค่านิ่งตาม `sim` ของ preset |
| Random walk | สุ่มเดินไปมาในช่วง min..max ไม่กระโดดแรง บูลีนสลับเป็นครั้งคราว |
| Loop | ไล่ค่าจาก min ขึ้น max แล้ววนกลับเป็นรอบ (ฟันเลื่อย) enum/บูลีนวนทีละสถานะ |
| Sine | คลื่นไซน์เรียบ แต่ละจุดเฟสต่างกัน |
| Device behaviour | ทำตัวตามชนิดอุปกรณ์ ดูด้านล่าง |
| Preset's own patterns | ขยับเฉพาะจุดที่ preset กำหนด `sim_pattern` เอง |

**พฤติกรรมตามชนิดอุปกรณ์ (Device behaviour):**
- **meter:** แรงดันนิ่งรอบค่าตั้งต้นมีสั่นเล็กน้อย, กระแสและกำลังตามโหลดที่ขึ้นลงช้า ๆ, พลังงานสะสมเพิ่มขึ้นอย่างเดียว
- **drive:** วงจรมอเตอร์ หยุด 5 วินาที เร่ง 10 วินาที วิ่ง 25 วินาที ลด 10 วินาที ความถี่ กระแส รอบ ตามความเร็ว อุณหภูมิขึ้นตามโหลด
- **level:** ระดับในถังขึ้นลงช้า ๆ (รอบละ 2 นาที)
- **pressure:** สุ่มเดินรอบค่าตั้ง **flow:** อัตราไหลผันผวน ตัวสะสมปริมาตรเพิ่มขึ้นอย่างเดียว
- **temperature:** ค่าล่องช้าพร้อมสัญญาณรบกวน **io:** บูลีนสลับหลายจังหวะ อนาล็อกเป็นคลื่น
- ค่าตั้งค่า (baud, address, ช่วงวัด ฯลฯ) ไม่ขยับ ตัวนับ (errors, hours) เพิ่มอย่างเดียว

ชนิดอุปกรณ์เดาจากชื่อ/หน่วยของ preset หรือใส่ `"device_type": "drive"` ใน preset ก็ได้ (meter, drive, level, pressure, flow, temperature, io, generic)

**จุดที่ master เขียนได้ (access rw) และข้อความจะไม่ถูกขยับ** ค่า setpoint ที่ master เขียนเข้ามาจึงคงอยู่

**กำหนดการขยับเองในไฟล์ preset:**
```
{"name": "Flow", "address": 0, "type": "float32", "unit": "m3/h", "sim": 12.5,
 "sim_pattern": {"kind": "random_walk", "min": 5, "max": 20, "step": 0.05}}
```
ชนิด (`kind`): `fixed`, `noise`, `random_walk`, `sine`, `ramp`, `triangle`, `square`, `sequence` (`values`, `hold` วินาที), `counter` (`start`, `rate` ต่อวินาที), `follow` (`signal` = load หรือ speed) ตัวเลือกร่วม: `min`, `max`, `period` (วินาที), `phase`, `noise`

**ใช้จาก CLI และ AI:** `python mbtool.py sim --preset ไฟล์.json --signals profile [--device-type drive] [--speed 2]` หรือเครื่องมือ MCP `sim_start` แล้ว `sim_load_preset` ดู [[slave-sim]] [[preset-schema]]

ข้อควรรู้: ค่าที่ได้เป็นการจำลองเพื่อทดสอบโปรแกรม ไม่ใช่ข้อมูลจากอุปกรณ์จริง และ preset ไลบรารีทั้งหมดยังเป็น UNVERIFIED

## AI Assist (F12)
<!-- id: ai-assist | category: ฟีเจอร์ในโปรแกรม | keywords: ai assist f12 claude chatgpt mcp token แชร์ วิเคราะห์ รายงาน -->
ให้ AI ช่วยวิเคราะห์อุปกรณ์ของคุณได้สองทาง

1. **แชร์การเชื่อมต่อสด:** เปิดเซิร์ฟเวอร์ MCP ในโปรแกรม AI ที่รองรับ MCP เชื่อมมาอ่านค่าจากอุปกรณ์ที่คุณเชื่อมอยู่ได้ (อ่านอย่างเดียว) ต้องมี token
   - **ใครเชื่อมได้:** "Only this PC" (ค่าเริ่มต้น) หรือ "Other computers on my network" ซึ่งมีหน้าต่างยืนยัน เพราะข้ามเครือข่ายเป็น HTTP ธรรมดา แนะนำ VPN เช่น Tailscale
   - **พอร์ต** ค่าเริ่มต้น 8765 (ขึ้นข้อความถ้าพอร์ตถูกใช้อยู่)
   - **"Let the AI choose the device"** ปิดไว้ ถ้าปิด AI เปลี่ยนอุปกรณ์ ต่อ ตัด หรือสแกนพอร์ตเองไม่ได้ และการเขียนค่าถูกปิดตลอด
   - **Token** ซ่อน/แสดง คัดลอก สร้างใหม่ได้ (สร้างใหม่แล้ว token เก่าใช้ไม่ได้) ไม่ถูกบันทึกลงไฟล์ใด
   - มีมุมมองบันทึกการเรียกใช้สด (ล็อกอินผิดเป็นสีแดง) และป้ายเหลืองบนแถบสถานะ
   ดู [[mcp-security]]
2. **คัดลอกรายงานวินิจฉัย:** สร้างรายงาน (ตัวอย่างค่า การตีความ traffic error และ checklist) ไปวางในแชตของ AI ตัวใดก็ได้ ตรวจรายงานก่อนส่งขึ้นบริการคลาวด์ เพราะมีค่าและ traffic ของอุปกรณ์
